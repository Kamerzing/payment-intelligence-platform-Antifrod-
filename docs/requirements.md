# Требования первой версии

## Назначение

Закрытый пилот с тестовыми RUB-средствами: проведение операций в Java Payment Core, блокирующая проверка антифрода, расследования и локальный ИИ-анализ. Первое окружение — ПК пользователя; основной режим разработки — local-lite.

Платформа не проводит деньги и не имеет публичной регистрации. Реализованы оценка риска, события и витрина, проверка расходных команд ядра, кабинет ADMIN, расследования с аудитом и фоновый локальный ИИ. Прямые предметные браузерные API платформы закрыты: пользователь работает через защищённый шлюз и сессию ядра. Контракт и эксплуатация: [integration.md](integration.md), [stages-5-6.md](stages-5-6.md), [stages-7-8.md](stages-7-8.md). Готовность пилота определяется фактическими проверками, а не наличием кода.

Требования этапа 7: генерация выключена по умолчанию; закреплённые локальные Qwen3/Q4 и runtime; один воркер и восемь активных заданий; неизменяемый снимок; актуальные права ADMIN для каждого инструмента; ограниченный JSON с проверкой всех фактов; явный fallback по правилам; отсутствие денежных инструментов и внешнего fallback. Требования этапа 8: сквозная проверка двух JAR и браузера, конкурентность/повторы, измерение p95 при 5 запросах/с, доставка до 5 секунд, парная копия БД при остановленных писателях, восстановление в отдельные пустые БД, сверка и сохранность денежных ключей.

## Предметные требования пилота

Реализованные требования этапов 3–4: атомарность outbox и движения в ядре; стабильные event_id и курсор; подтверждение после commit; сохранённые повторы с backoff; дедупликация и защита порядка; согласованный экспорт с возобновлением импорта; четыре исходных правила с версиями; атомарные счётчики по кошельку; неизменяемая история решений; окончательный DENY и ограниченный срок ALLOW; повторы не добавляют попытки. Точные границы и DTO описаны в [интеграции](integration.md) и [OpenAPI](openapi/internal-v1.yaml).

Для перевода, вывода и списания резерва ядро получает ALLOW/DENY до проведения. DENY не создаёт проводок. При недоступной проверке возвращается техническая ошибка без списания и с безопасным повтором исходного ключа. Правила, суммы, идемпотентность и случаи резервов подробно закреплены в [AGENTS.md](../AGENTS.md) и [плане](implementation-plan.md).

ADMIN ядра анализирует историю и расследования через защищённый шлюз. Локальный агент использует только разрешённые инструменты чтения, объясняет риск на русском языке и ссылается на факты. При отсутствии модели остаются объяснения правил; автоматических денежных действий нет.

Карточные данные, банковские интеграции, настоящие средства, Android, ML-обучение и постоянный сервер не входят в стартовую реализацию.
